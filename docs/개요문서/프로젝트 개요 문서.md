# 프로젝트 구조

처음 이 저장소를 받은 사람이 "무엇이 어디 있고, 뭘 고치려면 어디를 열어야 하는지"를
알기 위한 문서다.

- 이 문서: **어디에 무엇이 있나**
- [동작원리.md](동작원리.md): **왜 그렇게 도나** (한 번의 대화가 흐르는 순서, 설계 이유)

먼저 이 문서를 읽고, 고칠 파일을 찾은 다음, 그 부분의 배경이 궁금하면 동작원리를 본다.

---

## 1. 이 프로그램이 하는 일

사용자가 **말하거나 입력하면**, 화면 속 메타휴먼이 **한국어로 대답하고 입을 움직인다.**

```
사람 ──말──▶ [ 받아적기 ] ──글자──▶ [ LLM ] ──답 문장──▶ [ 음성 합성 ]
                                                              │
                                            소리 + 입모양 타임라인
                                                              ▼
                                              [ 메타휴먼이 말하며 입을 움직임 ]
```

외부 API를 쓰지 않는다. 모델이 전부 로컬(또는 사내 PC)에서 돈다.

### 알아둘 용어

| 용어 | 뜻 |
|---|---|
| **STT** (Speech-to-Text) | 소리를 글자로. 여기선 faster-whisper |
| **LLM** | 답 문장을 만드는 언어 모델. 여기선 원격 llama.cpp의 EXAONE |
| **TTS** (Text-to-Speech) | 글자를 소리로. 여기선 MeloTTS |
| **강제 정렬** (forced alignment) | 만들어진 소리에서 "이 음절이 몇 ms부터 몇 ms까지 발음되는지" 찾는 것 |
| **viseme** | 입 모양 하나. 소리(음소)의 시각적 짝. `아` 소리엔 입이 벌어진 모양 |
| **프레임** | 서버가 WebSocket으로 보내는 JSON 한 덩어리. `speech` 프레임엔 문장·오디오·viseme 타임라인이 함께 들어 있다 |

## 2. 저장소 지도

```
Local_Conversational_AI/
├── server/          파이썬 백엔드. 모델은 전부 여기서 돈다
├── UE5_Client/      언리얼 엔진 5.8 클라이언트. 화면과 마이크와 스피커
├── docs/            설계·동작 문서
```

**서버와 클라이언트는 완전히 분리돼 있다.** 둘 사이의 유일한 접점은
`ws://localhost:8000/ws` WebSocket 하나다. 그래서 서버만 켜 두고
`server/scripts/ws_client.py`로 대화를 테스트할 수 있다 — 언리얼을 띄우지 않아도 된다.

## 3. 서버 (`server/`)

```
server/
├── app/             실제 코드
├── tests/           단위 테스트 70개. 모델 없이 1초 안에 끝난다
├── scripts/         손으로 돌려보는 확인용 스크립트
├── requirements.txt
├── run.bat          서버 실행
├── restart.bat      8000 포트를 잡은 서버를 죽이고 다시 실행 ← 평소엔 이걸 쓴다
└── README.md        설치·환경변수·LLM 서버 교체 방법
```

### `app/` 모듈별 역할

**위에서 아래로 갈수록 작고 단순해진다.** 아래쪽 모듈은 아무것도 import하지 않는
순수 함수라 테스트하기 쉽다.

| 파일 | 하는 일 | 이걸 고치고 싶을 때 |
|---|---|---|
| `main.py` | FastAPI 앱, WebSocket 엔드포인트, 모델 사전 로딩 | 새 메시지 타입 추가, 접속 처리 |
| `session.py` | 연결 하나의 대화 히스토리, 한 턴의 진행 | 히스토리 길이, 턴 순서 |
| `llm.py` | LLM 스트리밍 호출 (Ollama / OpenAI 호환 두 방식) | 다른 LLM 서버 붙이기 |
| `stt.py` | faster-whisper로 WAV를 글자로 | 인식 모델·옵션 |
| `sentence.py` | 토큰이 흘러오는 걸 문장 단위로 자르기 | 문장 끊는 기준 |
| `pipeline.py` | 문장 하나를 `speech` 프레임으로 조립, 실패 시 폴백 | 프레임 구성 |
| `tts.py` | 음성 합성 (MeloTTS / XTTS), WAV 인코딩 | TTS 엔진 교체 |
| `align.py` | 음절이 몇 ms에 발음되는지 계산 | 정렬 정확도 |
| `viseme.py` | 음절 → 입 모양 이름 | 입 모양 매핑 규칙 |
| `hangul.py` | 한글을 초성·중성·종성으로 분해 | 자모 처리 |
| `config.py` | 환경변수 설정, **시스템 프롬프트** | AI 말투 바꾸기 |

의존 방향은 한쪽으로만 흐른다. 순환 import가 없다.

```
main ─▶ session ─▶ pipeline ─▶ tts, align, viseme ─▶ hangul
  └──▶ stt
```

`stt`가 `session`을 거치지 않는 게 눈에 띌 텐데, **받아적기는 대화 턴이 아니기
때문이다.** 서버는 WAV를 받아 글자로 바꿔 돌려줄 뿐이고, 그 글자로 무엇을 할지는
클라이언트가 정한다.

### 서버가 주고받는 메시지

WebSocket으로 오가는 JSON은 네 종류뿐이다.

**클라이언트 → 서버**

| type | 내용 | 서버 반응 |
|---|---|---|
| `user_message` | `text` | 대화 턴을 돌린다. `speech` 프레임을 여러 개 보낸다 |
| `audio_message` | `audioBase64` (WAV) | 받아적어 `transcript` 하나만 보낸다. LLM·TTS를 타지 않는다 |

**서버 → 클라이언트**

| type | 내용 |
|---|---|
| `speech` | 문장 하나 + 그 문장의 오디오 + viseme 타임라인 |
| `transcript` | 받아적은 글자. 아무 말도 없었으면 빈 문자열 |
| `error` | `code`, `message` |

한 문장이 완성될 때마다 `speech`가 나가므로, LLM이 답을 다 만들기 전에 첫 문장이
이미 재생되고 있다.

## 4. 클라이언트 (`UE5_Client/`)

```
UE5_Client/
├── Source/UE5_Client/   C++ 코드
├── Content/             언리얼 에셋 (.uasset, .umap)
│   ├── Maps/Main.umap           실행되는 레벨
│   ├── UI/WBP_Conversation.uasset  대화 UI 블루프린트
│   └── MetaHumans/              ★ 저장소에 없다. 직접 받아야 한다
├── Config/              엔진 설정 ini
└── UE5_Client.uproject
```

### C++ 클래스별 역할

다섯 개뿐이다. 넷은 `UGameInstanceSubsystem`(게임이 도는 동안 하나만 존재)이고,
`VisemeDriver`만 액터에 붙이는 컴포넌트다.

| 클래스 | 하는 일 | 이걸 고치고 싶을 때 |
|---|---|---|
| `ConversationClient` | WebSocket 소유, 프레임 파싱, 끊기면 재연결 | 서버 주소, 재연결 정책, 새 프레임 처리 |
| `MicRecorder` | 마이크 캡처, WAV 조립, **말이 끝났는지 판단** | 무음 감지 임계값 |
| `SpeechQueue` | 받은 문장 오디오를 겹치지 않게 순서대로 재생 | 재생 순서, 끊기 |
| `VisemeDriver` | 재생 위치 → 메타휴먼 얼굴 커브값 | 입 모양 세기, 보간 |
| `ConversationWidget` | UI 상태 기계. 대화 모드, 마이크 개폐, **언제 보낼지** | 화면 동작 대부분 |

`ConversationWidget`이 제일 크다(약 500줄). 다른 넷은 각자 한 가지만 한다.

### 대화 모드 두 가지

시작하면 모드 선택 화면이 뜬다. 마이크를 열고 실시간으로 받아적는 건 둘이 같고,
**언제 LLM으로 보내느냐**가 다르다.

| | 실시간 대화 | 푸시 투 토크 |
|---|---|---|
| 시작 | 고르는 즉시 마이크가 열린다 | 마이크 버튼을 눌러야 열린다 |
| 말을 멈추면 | 2초 뒤 자동 전송 | 계속 녹음 |
| 마이크 버튼 재누름 | 취소 (녹음 버림) | "말 다 했다" — 글자가 입력란에 남는다 |
| 인식 오류 수정 | 못 한다 | 입력란에서 고친 뒤 엔터 |

오른쪽 위 `ModeLabel`이 지금 상태를 한 줄로 보여준다:
`● 녹음 중` → `텍스트로 변환 중...` → `AI 말하는 중 — 마이크 꺼짐` → 모드 이름.

### 에디터에 반드시 있어야 하는 위젯 이름

`WBP_Conversation`은 아래 이름을 **정확히** 가진 위젯을 가져야 한다. 하나라도 없으면
블루프린트 컴파일이 실패한다 (`BindWidget`은 강제다).

| 이름 | 타입 |
|---|---|
| `InputBox` | MultiLineEditableTextBox |
| `SendButton` | Button |
| `MicButton` | Button |
| `ChatScroll` | ScrollBox — 안은 비워둔다. 말풍선은 런타임에 붙는다 |
| `ModePanel` | 아무 컨테이너 — 화면 전체를 덮어야 한다 |
| `RealtimeButton` | Button |
| `PushToTalkButton` | Button |
| `ModeButton` | Button |
| `ModeLabel` | TextBlock |

색·간격 같은 값은 코드를 고칠 필요 없이 위젯 디테일 패널의 **Conversation** 카테고리에서
바꾼다 (`UserBubbleColor`, `RecordingColor`, `MaxRecordSeconds`, `BubbleWidth` 등).

### PIE 중에 바꿀 수 있는 값 (콘솔 변수)

물결(`~`)을 눌러 입력한다.

| 명령 | 뜻 | 기본값 |
|---|---|---|
| `conv.MicDebug 1` | 마이크 RMS를 로그로 찍는다 | 0 |
| `conv.SpeechLevel 0.005` | 이 이상이면 말하는 중으로 본다 | 0.005 |
| `conv.SilenceMs 2000` | 이만큼 조용하면 말이 끝난 것으로 본다 | 2000 |

무음 감지가 안 걸리면 `conv.MicDebug 1`로 실제 값부터 본다. 조용할 때 0.0006,
말할 때 0.004~0.012쯤 나오는 게 정상이다.

## 6. 처음부터 돌려보기

### 1) 서버

```bash
cd server
python -m venv .venv
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/pip install --no-deps git+https://github.com/myshell-ai/MeloTTS.git
```

`--no-deps`가 빠지면 XTTS가 깨진다. 자세한 건 [server/README.md](../server/README.md).

```bash
restart.bat
```

**`모델 로딩 완료` 로그가 뜬 뒤에 접속한다.** TTS·정렬기·STT 셋을 올리느라 30초쯤 걸린다.

서버만 확인하려면:

```bash
.venv/Scripts/python scripts/ws_client.py "오늘 뭐 했어?"
```

### 2) 클라이언트

`UE5_Client.uproject`를 연다. C++을 고쳤으면 에디터가 빌드하겠냐고 묻는다.

메타휴먼 에셋은 저장소에 없다(900MB가 넘어 LFS 무료 할당을 넘긴다). MetaHuman
Creator에서 만들어 `Content/MetaHumans/`에 내려받는다. 이름이 `NewMetaHumanCharacter`가
아니면 `Main.umap`의 참조를 다시 잡아야 한다.

## 7. "이걸 바꾸고 싶은데 어디를 여나"

| 하고 싶은 것 | 열 파일 |
|---|---|
| AI 말투 바꾸기 (반말/존댓말, 길이) | `server/app/config.py`의 `system_prompt` |
| 다른 LLM 서버 붙이기 | `server/run.bat`의 환경변수. 코드는 `app/llm.py` |
| TTS 엔진 바꾸기 | 환경변수 `TTS_ENGINE`. 코드는 `app/tts.py` |

| 말풍선 모양·색 | 위젯 디테일 패널의 Conversation 카테고리 |
| 입 모양 매핑 | `server/app/viseme.py` |
| 얼굴 커브 적용 방식 | `UE5_Client/.../VisemeDriver.cpp` + Face AnimBP의 Modify Curve 노드 |

## 8. 미리 알면 시간을 아끼는 함정

**`.bat` 파일의 인코딩을 바꾸지 마라.** `run.bat`과 `restart.bat`은 CRLF 줄바꿈에
CP949다. cmd.exe는 배치 파일의 줄 위치를 바이트로 세기 때문에, UTF-8이나 LF로 저장하면
계산이 어긋나 한글 주석 중간부터 명령으로 실행해 버린다. 에디터가 조용히
바꿔놓는 일이 잦다.

**커밋 전에 `UE5_Client.uproject`를 확인해라.** 에디터를 한 번 열 때마다
`EngineAssociation`이 `"5.8"`에서 그 PC의 GUID로 바뀐다. 그대로 커밋하면 다른 사람이
프로젝트를 못 연다.

```bash
git checkout -- UE5_Client/UE5_Client.uproject
```

**C++ 빌드는 에디터를 닫고 해라.** 열려 있으면 DLL이 잠겨 빌드가 실패한다.

**Git LFS를 먼저 설치해라.** `.uasset` / `.umap` / `.wav`가 LFS로 관리된다. 없이
클론하면 에셋 대신 포인터 텍스트 파일이 들어온다.

**서버 코드를 고쳤으면 `restart.bat`이다.** `uvicorn --reload`는 파일이 바뀔 때마다
모델을 다시 올려서(30초) 쓸 수 없다.

## 9. 무엇을 고쳤는지 확인하는 법

| 고친 곳 | 확인 |
|---|---|
| 서버 순수 로직 | `.venv/Scripts/python -m pytest -v` (70개, 1초) |
| TTS | `scripts/smoke_tts.py melo` → `out/smoke_melo.wav` |
| 정렬 | `scripts/smoke_align.py` |
| STT | `scripts/smoke_stt.py` |
| 서버 전체 왕복 | `scripts/ws_client.py "질문"` |
| 클라이언트 | 에디터를 닫고 빌드 → PIE에서 직접 말해본다 |

클라이언트는 자동 테스트가 없다. PIE에서 직접 확인하는 수밖에 없다.
